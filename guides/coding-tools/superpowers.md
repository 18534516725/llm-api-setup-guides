# Superpowers 中文教程：安装与 AI 编程工作流实战

> 最后核验：2026-10-21。客户端入口依据官方 README；不同客户端分别安装。

[← 返回教程总目录](../教程总目录.md)

## Superpowers 解决什么问题

Superpowers 是为编程 Agent 提供开发方法和可组合 Skills 的项目。它把需求澄清、设计、计划、实现、调试与验证串成工作流。它不是模型服务，也不会自动增加模型上下文或 API 额度。

适合有代码仓库、希望改动可审查的开发任务。只改一句文案或问一个概念时，不需要人为扩成复杂工程流程。

## 1. 安装前先检查

1. 确认客户端名称和版本。
2. 查看是否已经装过 Superpowers 插件或手动 Skill。
3. 确认项目 Rules / AGENTS.md 中的用户要求。
4. 保留已有配置备份，避免插件和旧手动安装同时触发。

插件安装在客户端环境，项目规则属于仓库环境，两者不要混为一谈。

## 2. Claude Code 安装

在 Claude Code 的交互会话里执行，不是在系统 Shell 里执行：

```text
/plugin install superpowers@claude-plugins-official
```

官方还提供自己的 marketplace 路径：

```text
/plugin marketplace add obra/superpowers-marketplace
/plugin install superpowers@superpowers-marketplace
```

选择一条安装来源即可，安装后按客户端提示重新载入。不要同时安装两个来源来“提高生效概率”。

## 3. Codex 与 Cursor 安装

当前官方 README 为 Codex App 提供插件市场入口：在 Plugins 中找到 Superpowers 安装。Codex CLI 可通过 `/plugins` 搜索安装。Cursor 在插件市场搜索 Superpowers，官方 README 也列出 `/add-plugin superpowers` 入口。

客户端界面发生变化时，以对应版本的插件管理页和官方安装说明为准。不要把 Claude Code 的 `/plugin` 命令直接粘到其他客户端。

## 4. 用一个小改动验证

在一个干净测试仓库中提出明确需求：

```text
给现有 CSV 导入功能增加空文件提示。
先读现有实现和相关测试，说明触发条件与用户看到的结果。
完成实现、相关验证和变更说明，保留现有其他改动。
```

观察它是否先理解上下文、给出可检查方案，并在实现后运行有关验证。插件名称出现在列表里，只能证明安装记录存在。

## 5. 工作流各阶段看什么

| 阶段 | 你需要检查的产物 |
|---|---|
| 需求与设计 | 触发条件、边界、最终行为是否清楚 |
| 实现计划 | 修改位置、依赖顺序和验证方式是否明确 |
| 实现 | 是否遵循现有结构，是否混入无关改动 |
| 调试 | 是否先找到证据，再提出修复 |
| 验证 | 是否真的执行了检查，并报告输出 |
| 收尾 | 提交、推送、部署三个状态是否分别说明 |

## 6. 与 Rules、Skills、MCP 的关系

- Rules / AGENTS.md 定义项目约束，例如包管理器与部署流程。
- Skills 定义针对某类任务的方法。
- MCP 提供可调用的外部工具。
- Superpowers 组织开发方法，本身不会授予账户、生产部署或外部写入权限。

已经使用项目专用工作流时，明确哪一套负责计划、哪一套负责验证，避免多套插件重复生成相似文档。

## 7. 如何控制时间与成本

先把目标拆到可以独立验收的小范围，再选择适合的流程。记录一轮任务的修改文件、模型消耗和返工次数，比较安装前后的实际质量；不要把“调用了更多 Skills”直接当作效果更好。

若会启动子 Agent，确保客户端支持，并遵守用户是否授权并行工作的要求。测试不能只验证“函数被调用”，要覆盖真实需求。

## 8. 常见问题

| 问题 | 处理方式 |
|---|---|
| 安装后没有触发 | 重新载入、确认启用状态与当前任务匹配情况 |
| 同样内容反复询问 | 明确已经确认的需求，检查重复安装和规则冲突 |
| 只写计划不实现 | 明确任务是执行到验证完成，并检查是否确有待决选择 |
| 测试通过但功能不对 | 回到验收条件，检查测试是否覆盖用户行为 |
| 客户端不支持安装命令 | 使用该客户端官方安装路径 |

## 9. 更新与卸载

通过原安装渠道更新。卸载时先记录来源和作用域，只删除对应插件或明确由其生成的配置；不要清空整个 Skills 目录。团队项目应把稳定的项目规则放在仓库，让插件更新不会悄悄改变关键发布约束。

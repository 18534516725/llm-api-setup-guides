# MinerU、Docling、MarkItDown 怎么选：PDF 解析对比与测试方法

> 最后核验：2026-10-21。能力整理依据各项目官方文档；本文没有运行统一性能基准，不提供虚构速度或准确率。

[← 返回教程总目录](../教程总目录.md)

## 先按文件类型选择

普通 Office 文字提取可从 MarkItDown 起步；需要统一文档结构和可配置 Pipeline 可评估 Docling；中文扫描件、公式和复杂 PDF 可把 MinerU 纳入同文件对照。最终选择应由自己的文档与验收指标决定。

| 需求 | 优先试验路径 | 必须检查 |
|---|---|---|
| Word / PPT / Excel 转文字 | MarkItDown，再对照其他工具 | 标题、表头、幻灯片顺序 |
| PDF 多栏和表格 | Docling 与 MinerU | 阅读顺序、跨页、合并单元格 |
| 中文扫描件 | MinerU 与 Docling OCR | 旋转、分辨率、数字与单位 |
| 公式 / 学术论文 | 用代表性页面比较 | 公式缺失、符号和脚注 |
| 统一结构接入 RAG | Docling / MinerU 输出设计 | 页码、原件、来源关联 |
| 离线部署 | 分别准备依赖与模型缓存 | 首次下载、运行联网与许可 |

这些是试验起点，不是对所有文件通用的排名。

## 1. 版本基线

本批安装教程分别固定 MinerU 4.0.12、Docling 2.141.0、MarkItDown 0.1.8。各工具使用独立虚拟环境，避免互相修改依赖。不要让某个工具启用远程高性能服务、另一个只用 CPU，却只比较最终秒数。

## 2. 准备最小测试集

选择你有权处理的 8 份短文件：

1. 有文字层的中文 PDF。
2. 没有文字层的中文扫描件。
3. 两栏英文论文。
4. 有跨页表格的报告。
5. 公式密集页面。
6. 带嵌入图片的 DOCX。
7. 含多个文本框的 PPTX。
8. 多 Sheet、含日期和公式的 XLSX。

为每份文件记录来源、哈希、页数、语言和格式；固定相同输入，不在比较过程中偷偷换样本。

## 3. 建立人工答案

每份文件标注 5～10 个可核对事实，例如标题、日期、总金额、表格单元格、公式符号与原页位置。答案应来自原件，而不是某个工具的输出。

不要只用大模型给另一个大模型打分。模型可以辅助发现疑点，但关键字段用人工 / 程序校验。

| sample-01 | 自己填写 | 自己测量 | 自己测量 | 自己核对 | 是 / 否 | 具体问题 | 自己测量 |

首次模型下载、首次初始化和重复运行分别记录。吞吐需标明硬件、并发、后端与文件大小。

## 5. 不要只看 OCR 字数

“收入 1,000 万元”和“收入 100 万元”长度相近，事实差别很大。关注：

- 数字、负号、小数点、日期和单位；
- 表格字段对应关系；
- 章节和阅读顺序；
- 页眉页脚与正文的混入；
- 图片与公式是否被遗漏；
- 能否回到原页验证。

## 6. 用真实 RAG 问题复验

将三种输出分别导入相同切块、Embedding 和检索配置。使用同一组问题，比较来源命中、正确回答、引用页码和拒答情况。不要同时更换解析器与模型，否则无法判断改善来自哪里。

检索结果最好先看原始片段，再看最终回答。模型能猜对答案，不能证明检索正确。

## 7. 估算总成本

总成本包含计算、模型 / OCR 服务、存储、失败重试和人工纠错。一次解析快，但需要长期手工修表，不一定更便宜。

生产前再验证大文件、损坏文件、超时、取消、批量部分失败和恢复。解析后只发布自己可公开的示例，不把客户原件带入仓库。

## 8. 常见选择问题

**只做 Office 转文字，需要 GPU 吗？** 不应先假定需要；先跑格式所需的基础转换。

**安装成功就能离线吗？** 不一定。模型资产、系统依赖与运行后端要另外准备。

**Markdown 非空就是成功吗？** 不是，要看事实、结构和来源覆盖。

**可以多工具组合吗？** 可以，按文档类型分流，但要保存解析器和版本，避免后续无法复现。
